> ordering/idempotency scenarios with a throwaway test file (deleted after). Two
> scenarios were already green (duplicate `deleted` twice; late older

>
> **Same-second out-of-order downgrade.** `customer.subscription.created` is
> causally the first event for a subscription — Stripe never emits it after an
> `updated`/`deleted` for the same subscription. But the guard rejected only
> events strictly older by second (`<`). A `created` (STARTER) delivered *after* a

> issue forbids.

> Fix: `guardedWrite` gained a `rejectConcurrent` flag. The `created` branch
> passes `true`, widening its guard to older-or-same-second (`<=`); every other
> event type keeps `<` so a genuine same-second checkout progression
> (`created` -> `updated`, in order) still applies. This keeps the existing test
> "applies a distinct event that shares a timestamp with the last one" green
> (there `created` arrives first, so its guard never triggers).
>
> RED test added: "does not let a same-second created delivered after an update
> move the tier back" — confirmed failing (returned `updated`/STARTER) before the
> fix, passing (`stale_event`/PREMIUM) after.

> ## Dead ends / trade-offs (don't repeat)
>
> - Do NOT try to also protect same-second out-of-order for `updated`/`deleted`
>   via `<=`: a same-second cancellation (`deleted`) arriving after an `updated`
